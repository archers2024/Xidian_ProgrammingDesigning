# 服务器部署步骤

`deploy/` 是给「2 核 2G、大陆公网 IP、Ubuntu 22.04」准备的部署包。目标：`Nginx:80 → jar:8080 → 本机 MySQL`，前端静态资源由 Nginx 直接托管，jar 由 systemd 常驻。

## 1. 选机器

阿里云有面向在校生的优惠计划（高校计划 /「云工开物」等，名称和额度会随活动调整，以控制台当前页面为准，完成学生认证后领取）。课程演示用 2 核 2G、40G 系统盘、1~3M 带宽的 ECS 足够，系统选 Ubuntu 22.04 LTS。

安全组放行：`22`（SSH）、`80`（HTTP）、`443`（后续 HTTPS）。**不要**放行 3306 和 8080 到公网，MySQL 和 jar 只监听本机。

大陆节点用域名访问需要 ICP 备案；只用公网 IP + HTTP 演示不需要备案，但浏览器定位接口会被禁用（见第 6 节）。

## 2. 本机先构建

```bash
cd backend && mvn -DskipTests clean package       # target/activity-system-1.0.0.jar
cd ../frontend && npm ci && npm run build         # dist/
```

`deploy/upload.sh` 只传 jar、dist、init.sql 和 deploy 下的配置，不传 `node_modules` 与源码。

## 3. 上传

Windows 10/11 自带 OpenSSH 客户端，在 Git Bash 里执行：

```bash
cd <ROOT>/deploy
bash upload.sh root@<公网IP>
```

脚本会在服务器 `~/activity-system-pkg/` 下放好：

```
activity-system-pkg/
├── activity-system-1.0.0.jar
├── init.sql
├── dist/                # 前端构建产物
└── deploy/              # 配置与 setup.sh
```

`setup.sh` 里 `PKG_DIR` 取的是脚本所在目录的父级，所以上传后的目录结构必须保持上面这个层级，别把文件摊平。没有 scp 就用 WinSCP / FinalShell 手动传，结构一致即可。

## 4. 一键安装

```bash
cd ~/activity-system-pkg
sudo bash deploy/setup.sh <公网IP> [数据库密码]
```

`setup.sh` 依次做 10 件事：检查上传文件 → 装 openjdk-17 / mysql-server / nginx → 设时区与 2G swap → 建库导数据 → 写外置生产配置（替换 `__PUBLIC_IP__` / `__DB_PASSWORD__` / `__JWT_SECRET__`）→ 装 `mysql-lowmem.cnf` → 部署 dist 与 jar → 装 `nginx.conf` 并移除默认站点 → 装 `activity-system.service` → 启动并健康检查。可重复执行，检测到已有数据表会跳过 init.sql，不清空数据。

关键配置：

| 项 | 值 / 说明 |
| --- | --- |
| 后端 | `java -Xmx512m -jar ... --spring.config.additional-location=/opt/activity-system/config/application-prod.yml` |
| Nginx | `location /api/v1/ { proxy_pass http://127.0.0.1:8080/; }`，结尾斜杠剥前缀 |
| 静态资源 | `/assets/` 30 天强缓存，其余 `try_files ... /index.html` 支持 history 路由 |
| gzip | 开启，首屏 JS 约 1.1 MB，1M 带宽必须压缩 |
| 真实 IP | `RemoteIpValve` 依据 `X-Forwarded-For` 还原，否则报名限流会把全校当成一个 IP |
| 二维码 | `campus.mobile.base-url=http://<公网IP>/m`，不能留 localhost |
| 文件 | `/api/v1/files/` 由后端映射，Nginx 不直接暴露 uploads 目录 |

## 5. 验证

```bash
bash deploy/smoke-test.sh
curl http://<公网IP>/api/v1/dict/activity-type
sudo systemctl status activity-system
sudo journalctl -u activity-system -n 100 --no-pager
```

浏览器打开 `http://<公网IP>`，用 `admin / admin123` 登录，走一遍 `docs/02-运行步骤.md` 第 4 节的主链路。手机扫码时确认二维码内容是公网 IP 而不是 localhost。

## 6. HTTPS 与准确签到

浏览器只在安全上下文（HTTPS 或 localhost）提供 `navigator.geolocation`。要演示「准确签到」（动态码 + 地理围栏），必须：

1. 准备已备案域名并解析到服务器；
2. 用 Let's Encrypt 签发证书，在 Nginx 加 443 监听并把 80 跳转过来；
3. 把 `campus.mobile.base-url` 改成 `https://<域名>/m`；
4. 重启服务后重新生成二维码。

只用 IP + HTTP 时，走不带 `?code=` 的基本签到即可，别在现场纠结定位授权。

## 7. 运维命令

```bash
sudo systemctl restart activity-system
sudo systemctl stop activity-system
sudo journalctl -u activity-system -f
sudo nginx -t && sudo systemctl reload nginx
df -h; free -m                    # 小机器盯磁盘与内存
mysqldump -uroot -p campus_activity > backup.sql
```

更新版本：本机重新 `mvn package` / `npm run build` → `upload.sh` 重传 → 覆盖 `/opt/activity-system/` 下 jar 与 dist → `systemctl restart activity-system` → 跑冒烟。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动后 OOM 被 kill | 2G 内存同时跑 MySQL + JVM | 确认 swap 已建、jar 限 `-Xmx512m`、`mysql-lowmem.cnf` 已生效 |
| 后台接口 404 | Nginx 没剥 `/api/v1`，或后端又配了 context-path | `proxy_pass` 结尾加 `/`，后端保持根路径 |
| 所有接口免鉴权 | 旧版拦截器直接读 `getRequestURI()` | 用仓库里修好的 `LoginInterceptor` 重新打包 |
| 统计接口 50000 | `ONLY_FULL_GROUP_BY` | 按 `docs/02-运行步骤.md` 第 1.4 节设 `sql_mode` |
| 报名被限流误拦 | 反代后 `getRemoteAddr()` 全是 127.0.0.1 | 生产配置开 `RemoteIpValve`，或调大 `ip-limit-per-minute` |
| 二维码手机打不开 | `base-url` 是 localhost | 改成公网 IP / 域名 |
| 首屏加载很慢 | 1M 带宽未开 gzip | 确认 `nginx.conf` 的 gzip 段已启用 |
| 深链刷新 404 | 缺 history 回退 | `try_files $uri $uri/ /index.html` |
