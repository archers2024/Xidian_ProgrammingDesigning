# 实现步骤（从需求到可验收系统）

本文按实际施工顺序记录整个工程是怎么搭起来的：每一步做什么、落在哪些文件、用什么命令验证。照着做可以复现出仓库里这份代码；排错时先看第 13 节。

## 0. 总体路线

| 阶段 | 目标 | 主要产出 | 验收方式 |
| --- | --- | --- | --- |
| 0 | 环境准备 | JDK / Maven / MySQL / Node 可用 | 四条版本命令都有输出 |
| 1 | 数据模型 | 8 张表 + 字典数据 | `show tables` 得到 8 张表 |
| 2 | 后端公共基座 | 统一响应、异常、JWT、拦截器、定时任务 | 登录接口返回 token |
| 3 | 活动域 | 活动 CRUD、状态机、发布、字典 | 能建活动、能发布 |
| 4 | 报名域 | 宣传页、报名校验、名单导出 | 手机页可提交报名 |
| 5 | 签到与统计域 | 动态码、围栏、签到、统计 | 大屏出码、能签到、能出图 |
| 6 | 前端 | PC 8 页 + H5 4 页 | 页面能登录、能走完主链路 |

## 1. 需求拆解与模块边界

需求按「谁在用、操作什么数据」切成四个域，域之间只通过 Service 与字典表交互，不允许跨域直接写别人的表：

| 域 | 职责 | 代码位置 | 主要表 |
| --- | --- | --- | --- |
| 公共基座 | 认证、统一响应、异常、文件、字典、定时任务 | `common/ config/ security/ util/` | `t_admin`、`t_operation_log` |
| 活动域 | 活动全生命周期、类型字典、附件 | `module/activity/` | `t_activity`、`t_activity_type`、`t_attachment` |
| 报名域 | 宣传页、名额、报名、名单、学院字典 | `module/signup/` | `t_registration`、`t_college` |
| 签到与统计域 | 动态码、地理围栏、签到、Excel、图表数据 | `module/checkin/` | `t_checkin` |

对外接口统一以 `/api/v1` 暴露（由网关加前缀），后端自身以根路径部署。认证边界按 URL 划分：`/auth/**`、`/promo/**`、`/signup`、`/checkin`、`/dict/**`、`/checkin/qrcode/**` 公开；`/admin/**` 需登录；`/super/**` 需超级管理员。

## 2. 阶段 0：环境准备

本机验证通过的组合：Windows 11 + JDK 25（编译目标 17）+ Maven + MySQL 8.0 + Node 20。

```bash
java -version        # 需 17 及以上
mvn -v
mysql --version      # 8.0.x
node -v              # 18+，推荐 20
npm -v
```

`backend/pom.xml` 用 `spring-boot-starter-parent 3.2.5`，`java.version=17`。工程**不用 Lombok**，全部显式 getter/setter/构造器——高版本 JDK 上 Lombok 注解处理器容易失效，去掉后小组同学不用装 IDE 插件，也不会因为 JDK 版本差异编译失败。

前端依赖固定在 `frontend/package.json` / `package-lock.json`，用 `npm ci` 而不是 `npm install` 保证版本一致。

## 3. 阶段 1：数据库

`db/init.sql` 一次完成建库、建表、字典初始化：

```bash
mysql --default-character-set=utf8mb4 -uroot -p < db/init.sql
```

`--default-character-set=utf8mb4` 不能省。Windows 客户端默认 GBK，直接 `< db/init.sql` 导入中文学院名会报 `ERROR 1366: Incorrect string value`。

8 张表：`t_admin`、`t_activity_type`、`t_activity`、`t_attachment`、`t_college`、`t_registration`、`t_checkin`、`t_operation_log`。设计要点：

- 活动类型、学院拆成独立字典表，消除传递依赖，满足第三范式；
- `t_activity.signed_count` 是**声明式冗余**，只为列表页避免 count 查询，在报名事务内与 `t_registration` 同步维护；
- `t_registration` 上 `uk_activity_phone(activity_id, phone)` 唯一索引兜底重复报名；
- 所有业务表带 `deleted` 逻辑删除字段，MyBatis-Plus 全局配置 `logic-delete-value: 1` / `logic-not-delete-value: 0`；
- 默认管理员不写在 SQL 里，由 `DataInitializer` 首次启动时检测 `t_admin` 为空后用 BCrypt 加盐写入 `admin / admin123`。

统计接口用到 `DATE_FORMAT` 分组，MySQL 8 默认开启 `ONLY_FULL_GROUP_BY`。两种处理方式：

```sql
-- 方式 A：会话级（推荐，只影响本次连接）
SET SESSION sql_mode=(SELECT REPLACE(@@sql_mode,'ONLY_FULL_GROUP_BY',''));

-- 方式 B：全局级（重启会失效，需写进 my.cnf 才持久）
SET GLOBAL sql_mode='STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION';
```

仓库里的 `CheckInMapper.statDaily` 已经把 `GROUP BY DATE(...)` 改成 `GROUP BY DATE_FORMAT(..., '%Y-%m-%d')`，与 SELECT 表达式一致，这一步属于双保险。

## 4. 阶段 2：后端公共基座

按顺序实现：

1. **统一响应与异常** — `common/R.java` 固定 `{code, message, data}`，`code=0` 为成功；`BusinessException` + `GlobalExceptionHandler` 把业务异常、参数校验异常、系统异常都转成统一结构，前端 axios 拦截器只认 `code===0`。
2. **Web 配置** — `config/WebConfig.java` 注册 CORS（`allowedOriginPatterns("*")`）、登录拦截器（`/ **`）、`/files/**` 到本地上传目录的静态映射。
3. **认证** — `security/JwtUtil.java`（JJWT，HMAC，8 小时）、`LoginInterceptor.java`、`AdminContext.java`（ThreadLocal 保存当前管理员，`afterCompletion` 必须 clear，否则线程池复用会串号）。
4. **默认数据与定时任务** — `DataInitializer.java` 建默认超管；`StatusRefreshJob.java` 按时间推进活动六态；`MybatisPlusConfig.java` 注册分页插件。
5. **工具类** — `QrCodeUtil`（ZXing）、`ExcelUtil`（POI）、`GeoUtil`（Haversine）。

拦截器是整套系统最容易出错的一处，最终实现：

```java
private String normalizePath(HttpServletRequest request) {
    String uri = request.getRequestURI();
    String ctx = request.getContextPath();
    if (ctx != null && !ctx.isEmpty() && uri.startsWith(ctx)) {
        uri = uri.substring(ctx.length());
    }
    if (uri.startsWith("/api/v1")) {
        uri = uri.substring("/api/v1".length());
    }
    return uri.isEmpty() ? "/" : uri;
}
// needLogin = uri.startsWith("/admin/") || uri.startsWith("/super/")
```

它同时兼容三种部署形态：jar 根路径直连、Nginx 原样转发 `/api/v1`、后端自带 `context-path=/api/v1`。早期版本直接用 `getRequestURI()`，在第三种形态下 URI 是 `/api/v1/admin/...`，判断失败会让所有后台接口裸奔（`created_by` 为 null、`/admin/current` NPE）。

**验收**：`POST /api/v1/auth/login` 带 `{"username":"admin","password":"admin123"}` 返回 token；不带 token 请求 `/api/v1/admin/current` 应返回 401。

## 5. 阶段 3：活动域

`module/activity/` 下的实现顺序：

1. 实体与 Mapper：`Activity`、`ActivityType`、`Attachment` 及对应 Mapper；`ActivityMapper.selectForUpdate` 用 `SELECT ... FOR UPDATE` 锁活动行，供报名扣名额复用。
2. `ActivityService`：CRUD + 六态状态机（草稿、报名中、待开始、进行中、已结束、已取消）+ 发布校验（必填项、时间顺序、名额）+ 附件增删。
3. `ActivityController`：`/admin/activity` 下的 8 个接口（建、改、删、发布、分页列表、详情、二维码数据、签到配置）。
4. `ActivityTypeController`：活动类型字典。

**时间格式**是这里的坑。前端 `el-date-picker` 给的是 `yyyy-MM-dd HH:mm:ss`，早期 `parseTime` 把空格替换成 `T` 后直接 `LocalDateTime.parse`，空格格式里带 `T` 的字符串并不合法，建活动必失败。最终实现：

```java
private static final DateTimeFormatter SPACE_FORMATTER =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
// 16 位补秒、10 位补 00:00:00；含空格用 SPACE_FORMATTER，否则用 ISO 解析
```

单类重编译时必须带 `-parameters`（`javac -parameters --release 17`），否则 `@RequestParam` 的参数名被擦除，Spring 拿不到 `current/size/keyword`，列表接口返回 `data: null`。

## 6. 阶段 4：报名域

`module/signup/`：

1. `SignupController`：`GET /promo/{guid}` 宣传页数据、`POST /signup` 提交、`GET /admin/activity/{id}/registrations` 名单、`GET .../registrations/export` Excel 导出。
2. `SignupService`：手机号与姓名校验、活动状态与截止时间校验、名额校验、重复报名校验、脱敏 `mask()`（默认导出与列表都脱敏，完整数据需显式传 `maskPhone=false`）。
3. 防超卖：报名事务内先 `selectForUpdate` 锁活动行，判断 `signed_count < quota`，再插报名记录并 `incrSignedCount`；唯一索引作为最后一道兜底。
4. 防刷：同 IP 每分钟上限（`campus.signup.ip-limit-per-minute`），内存计数；反代场景要开 `RemoteIpValve` 还原真实 IP，否则全校共用一个 127.0.0.1 计数，会被误拦。
5. `CollegeController`：学院字典；`ExcelUtil` 生成 xlsx，导出用浏览器直链，token 走 query 参数。

## 7. 阶段 5：签到与统计域

`module/checkin/`：

1. `CheckinService.codeOf`：TOTP（HMAC-SHA1，30 s 时间片，容忍前后 1 片偏差），密钥由活动 ID 与配置混合，签到码每 30 秒变化一次。
2. `GeoUtil`：Haversine 计算签到点与活动坐标距离，超过 `checkin_radius` 拒绝；同一设备指纹在 `device-interval-seconds` 内不允许重复签到。
3. `CheckinController`：`GET /checkin/qrcode/{activityId}` 给大屏出码、`POST /checkin` 提交、`GET /admin/activity/{id}/checkins` 记录、`.../checkins/export` 导出。
4. `StatisticsController` + `CheckInMapper`：按活动类型统计报名/签到、按日趋势、总览指标，供 ECharts 画图。

准确签到需要浏览器 `navigator.geolocation`，只在 HTTPS 或 `localhost` 下可用。HTTP + 局域网 IP 打开 H5 时定位会被浏览器拒绝，演示请走不带 `?code=` 的基本签到，或按 `docs/03-服务器部署.md` 配 HTTPS。

## 8. 阶段 6：前端

一个 Vite 工程同时承载 PC 后台和 H5：

1. `src/api/request.js`：axios 实例 `baseURL: '/api/v1'`，请求拦截注入 Bearer token，响应拦截只回传 `body.data`，401 清 token 跳 `/login`。
2. `src/api/index.js`：按域封装全部接口，另提供两个导出直链（浏览器无法带 Header，token 走 query）。
3. `src/router/index.js`：后台 8 路由（登录、活动列表/新建/编辑/详情、报名名单、签到记录、统计、账号管理）+ H5 4 路由（宣传页、报名页、签到页、签到大屏）；`createWebHistory` 需要服务端 history 回退。
4. `src/layout/AdminLayout.vue`：侧边栏 + 顶栏；`src/views/*` 是 PC 页面；`src/mobile/*` 是 H5 页面，共用一套样式变量。
5. `vite.config.js`：开发代理把 `/api/v1` 前缀剥掉再转发到 8080——后端是根路径部署，不剥前缀会 404：

```js
proxy: {
  '/api': {
    target: 'http://localhost:8080',
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/api\/v1/, '')
  }
}
```

6. 二维码：`campus.mobile.base-url + /signup/{guid}` 与签到大屏地址由后端拼好，前端用 `qrcode` 渲染；`base-url` 必须是手机能访问的地址，不能留 `localhost`。

## 9. 阶段 7：前后端联调

按这个顺序排，一次只改一个变量：

1. 数据库导入 → 8 张表 + 字典（活动类型 5 类、学院 7 个）；
2. 后端启动 → `curl http://localhost:8080/dict/activity-type` 有数据；
3. 登录 → 拿 token → 带 token 请求 `/admin/current` 返回管理员信息；
4. 建活动 → 列表 → 发布 → 宣传页 → 报名 → 报名名单；
5. 打开签到（SQL 见 `docs/02-运行步骤.md`）→ 大屏出码 → 基本签到 → 签到名单 → Excel 导出；
6. 统计总览 → 三个指标和趋势图。

代理干扰时，Windows 上 `curl http://localhost:8080` 可能返回 000，用 `curl --noproxy '*'` 或 Python 里 `ProxyHandler({})` 绕开环境变量里的 HTTP 代理。

**验收记录**（本机实测，全部 200）：登录、`/admin/current`、建活动、分页列表、发布、宣传页、报名、报名名单、开启签到、基本签到、签到名单、Excel 导出（xlsx 3620 bytes）、统计总览。

## 10. 阶段 8：构建与部署

```bash
cd backend && mvn -DskipTests package     # target/activity-system-1.0.0.jar
cd ../frontend && npm ci && npm run build  # dist/
```

`deploy/` 是给 2 核 2G 学生机准备的一键部署包：

| 文件 | 作用 |
| --- | --- |
| `upload.sh` | 本地打包上传 jar、dist、SQL 与配置到服务器 |
| `setup.sh` | 装依赖、建库、写生产配置、装 Nginx 站点与 systemd 服务 |
| `nginx.conf` | gzip、静态资源长缓存、`/api/v1/` 反代（尾斜杠剥前缀）、history 回退 |
| `application-prod.yml` | 外置生产配置：数据库、JWT、公网二维码地址、`RemoteIpValve` |
| `activity-system.service` | systemd 常驻，`-Xmx512m` 限制内存 |
| `mysql-lowmem.cnf` | 小内存 MySQL 参数 |
| `smoke-test.sh` | 部署后冒烟 |
| `demo-checkin.sql` | 演示前把活动改成可签到状态 |

小机器要点：加 2G swap、jar 限堆 512M、开 gzip（首屏 JS 约 1.1 MB，1M 带宽不开会明显卡）、二维码用公网 IP 而不是 localhost、ICP 备案与 HTTPS 见 `docs/03-服务器部署.md`。

## 12. 关键算法与取舍

| 点 | 实现 | 为什么 |
| --- | --- | --- |
| 名额防超卖 | `selectForUpdate` 行锁 + `incrSignedCount` 事务内维护 | 不引入 Redis 也能保证单机一致 |
| 重复报名 | `uk_activity_phone` 唯一索引 + 服务层预判 | 并发下索引是最终防线 |
| 动态防作弊签到 | TOTP 30 s + 容忍 1 片 + Haversine 围栏 + 设备间隔 | 截图转发二维码无效，人不在现场签不了 |
| 手机号脱敏 | `SignupService.mask`，导出默认脱敏 | 名单外发不泄漏完整号码 |
| 密码 | BCrypt 加盐 | 不存明文，脚本里也没有明文口令 |
| 状态推进 | `StatusRefreshJob` 定时 + 服务层状态机 | 无人操作也会自动进入「进行中/已结束」 |
| 国产库预留 | SQL 无方言，切库只改驱动与 `DbType` | 便于后续适配达梦 |

## 13. 踩坑记录（真实复现过的）

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| `Unsupported character encoding 'utf8mb4'` | JDBC URL 写了 `characterEncoding=utf8mb4`，Java 不认这个 charset 名 | 改 `characterEncoding=UTF-8`，或用启动参数覆盖 |
| 导入 SQL 报 `ERROR 1366` | Windows mysql 客户端默认 GBK | `mysql --default-character-set=utf8mb4` |
| 所有后台接口免鉴权、`created_by` 为 null、`/admin/current` NPE | 拦截器用 `getRequestURI()`，带 context-path 时前缀不匹配 | 统一 `normalizePath` 剥前缀（第 4 节） |
| 建活动 500 | `parseTime` 把空格格式替换成 `T` 后直接 parse | 用 `DateTimeFormatter` 分别处理（第 5 节） |
| 列表返回 `data: null` | 单类重编译漏 `-parameters`，`@RequestParam` 名丢失 | `javac -parameters --release 17` 重新编译并替换 jar 内 class |
| 统计接口 50000 | `ONLY_FULL_GROUP_BY` 下 GROUP BY 与 SELECT 表达式不一致 | 改分组表达式 + 调 `sql_mode` |
| `curl` 返回 000 | 环境变量 HTTP 代理拦截了 localhost 请求 | `curl --noproxy '*'` |
| 二维码扫开是 `localhost` | `campus.mobile.base-url` 没改成公网/局域网地址 | 启动参数 `--campus.mobile.base-url=http://<IP>/m` |
| H5 定位失败 | HTTP 非安全上下文禁用 geolocation | 用基本签到，或部署 HTTPS |
