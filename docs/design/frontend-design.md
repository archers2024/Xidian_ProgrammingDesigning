# 前端设计规范

适用工程：`frontend/`。本文件描述当前已实现的设计变量、布局、组件与动效约定；代码中的权威来源是 `frontend/src/styles/tokens.css`，两者需同步修改。

## 1 视觉方向

现代校园活动平台：深蓝品牌色、浅灰页面背景、白色内容卡片、克制的青绿点缀。

- 管理后台强调清晰与效率：信息密度适中、操作路径短、状态可一眼识别。
- 参与者页面强调活动吸引力与报名便利：大标题、封面、关键信息卡、固定底部报名按钮。
- 签到大屏强调远距离辨识：大字号、深色背景、单一视觉焦点（二维码与倒计时）。

## 2 设计变量

### 2.1 颜色

| 用途 | 变量 | 值 |
|---|---|---|
| 品牌主色 | `--brand-500` / `--brand` | `#1D4ED8` |
| 品牌悬停 | `--brand-hover` | `#1642C2` |
| 品牌按下 | `--brand-active` | `#12359B` |
| 品牌浅底 | `--brand-soft` | `#EAF0FF` |
| 青绿强调 | `--accent` | `#0E9F9F` |
| 页面背景 | `--bg-page` | `#F5F7FB` |
| 卡片背景 | `--bg-surface` | `#FFFFFF` |
| 主文字 | `--text` | `#172033` |
| 次级文字 | `--text-muted` | `#64748B` |
| 边框 | `--border` | `#E2E8F0` |
| 成功 / 提醒 / 错误 | `--success` / `--warning` / `--danger` | `#16A34A` / `#D97706` / `#DC2626` |

状态不只依靠颜色表达：`StatusTag` 同时输出文字，标签页与表单项均有文字提示。

### 2.2 间距、圆角、阴影

- 间距体系：4、8、12、16、24、32、48px（`--space-1` 至 `--space-7`）。
- 圆角：卡片 16px、弹窗 20px、输入框与按钮 12px、小控件 10px、标签胶囊 999px。
- 阴影：`--shadow-sm`（静止卡片）、`--shadow-card`（浮起卡片）、`--shadow-float`（弹窗与抽屉）。

### 2.3 字体与字号

- 字体栈优先系统中文字体：`PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`，不加载外部字体。
- 正文 14–16px；后台页面标题 28px（小屏 22px）；宣传页标题随屏幕在 26–38px 之间。
- 手机输入框字号 16px，避免 iOS 聚焦时页面缩放。

### 2.4 控件尺寸

| 场景 | 高度 |
|---|---|
| 后台输入框、按钮 | 40px（`--el-component-size`） |
| 后台主要按钮、登录表单 | 44px |
| 手机主要按钮 | 48px（`--control-height-mobile`） |
| 顶栏 | 64px（`--topbar-height`） |
| 侧边导航 | 224px（`--sidebar-width`） |

## 3 布局

### 3.1 管理后台

```text
┌──────────────┬──────────────────────────────────────┐
│ 侧边导航 224 │ 顶栏 64（面包屑 + 账号菜单）          │
│ 品牌/导航/页脚├──────────────────────────────────────┤
│              │ 内容区：最大 1320，边距 24–32        │
└──────────────┴──────────────────────────────────────┘
```

- 侧边导航与顶栏在页面切换时保持稳定，只有内容区参与转场。
- 内容区宽度上限 1320px，左右内边距 32px（小屏 16px）；页面内区块间距 16–24px。
- 工作台为统计卡网格 + 两列（近期活动 / 快捷入口）；宽度小于 1100px 时改为单列。
- 列表页顺序固定：页面标题与主操作 → 筛选区 → 数据区 → 分页。
- 宽度小于 1024px 时侧边导航改为抽屉，顶栏出现菜单按钮。

### 3.2 参与者页面

- 内容最大宽度 1080px，页面左右内边距 16px。
- 宣传页桌面双栏（内容 + 报名卡），小于 960px 单列；报名卡在手机端排到内容之后。
- 手机固定底部报名栏，内容区底部预留 `96px + safe-area-inset-bottom`，在 360 / 390 / 430px 宽度无横向滚动。
- 封面固定比例 16:7 并按比例裁剪，避免加载后推动按钮。

### 3.3 签到大屏

- 全屏深色渐变，左右两栏：左侧活动信息与人数，右侧二维码与倒计时。
- 标题随视口在 30–52px 之间，人数在 32–46px 之间，适合投影距离观看。
- 倒计时环使用 `conic-gradient`，只更新环与数字，不重绘整页。

## 4 组件规范

| 组件 | 位置 | 规则 |
|---|---|---|
| `PageHeader` | `components/common` | 标题 `h1`（`tabindex=-1`，导航后聚焦）、说明、返回按钮与操作插槽 |
| `StatusTag` | `components/common` | 固定映射四种展示状态：未发布 / 报名中 / 已截止 / 已结束 |
| `EmptyState` | `components/common` | 图标 + 标题 + 一句说明 + 可选操作，用于空列表与失效活动 |
| `ErrorState` | `components/common` | 标题、错误信息、业务码、重试按钮；不显示堆栈 |
| `LoadingSkeleton` | `components/common` | cards / list / table / detail 四种骨架屏 |
| `PlaceholderPanel` | `components/common` | 未完成能力用虚线卡片明确标注，列出后续批次内容，避免“能点但没实现” |
| `StatCard` | `components/common` | 统计卡，数值采用等宽数字 |
| `ActivityTable` | `components/activity` | 活动列表表格：名称/地点、类型、时间与截止、报名人数、状态、操作 |

按钮：主色实心用于页面主要动作，每屏最多一个；次要动作用描边或文字按钮；删除使用危险色并要求二次确认。

## 5 动效规范

| 场景 | 方案 | 时长 |
|---|---|---|
| 后台一级页面切换 | 淡入 + 上移 8px，退出淡出上移 4px | 进入 180ms / 退出 100ms |
| 手机页面前进 | 自右滑入 24px | 220ms（退出 120ms） |
| 手机页面返回 | 反向滑动 | 220ms（退出 120ms） |
| 卡片悬停 | 阴影加深 + 上移 1px | 120ms |
| 提交按钮 | 保持尺寸，显示加载态并禁用 | 请求期间 |
| 报名成功 | 勾选图标缩放出现 | 240ms |

实现约定：

1. 只动画 `opacity` 与 `transform`，不动画宽高、位置与模糊。
2. 后台转场写在 `AdminLayout` 的 `RouterView` + `Transition` 上，页面组件不各写一套。
3. 手机方向由 `PublicLayout` 比较前后路由的 `meta.depth` 判断。
4. 路由 `meta.transition` 可强制指定或关闭（签到大屏为 `none`）。
5. `prefers-reduced-motion: reduce` 下关闭位移与缩放，仅保留淡入淡出。

## 6 页面与路由

| 页面 | 路径 | 布局 | 鉴权 |
|---|---|---|---|
| 管理员登录 | `/admin/login` | blank | 否 |
| 工作台 | `/admin/dashboard` | admin | 是 |
| 活动列表 | `/admin/activities` | admin | 是 |
| 创建活动 | `/admin/activities/new` | admin | 是 |
| 活动详情 | `/admin/activities/:id?tab=basic|registrations|checkin` | admin | 是 |
| 编辑活动 | `/admin/activities/:id/edit` | admin | 是 |
| 签到大屏 | `/admin/activities/:id/screen` | blank | 是 |
| 宣传页 | `/events/:id` | public | 否 |
| 报名页 | `/events/:id/register` | public | 否 |
| 签到页 | `/checkin/:sessionId?token=…` | public | 否 |
| 404 | 任意未匹配路径 | public | 否 |

URL 约定：筛选 `keyword`、`typeId`、`status`、`dateFrom`、`dateTo`；分页 `page`、`pageSize`；详情标签 `tab`。进入详情再返回时筛选与分页条件保留。

## 7 状态与反馈

每个数据页面必须覆盖：加载中、空数据、加载失败、提交中、提交成功、业务失败。

- 加载超过约 150ms 才显示骨架屏，避免短请求闪烁；列表筛选变化时保留旧内容并降低透明度。
- 业务错误按 `code` 分支（如 `REGISTRATION_DUPLICATE`、`VERSION_CONFLICT`），中文文案只用于展示。
- 提交失败保留用户已填内容，提供重试；失败时不播放成功动画。
- 名额已满、已截止、已结束时保留活动信息，按钮显示原因而不是直接消失。
- 会话 401：清理前端身份并跳转登录页，登录后回到原地址。

## 8 可访问性与性能

- 键盘可达：表单、按钮、弹窗焦点清晰；导航后焦点移动到页面标题。
- 状态、错误同时使用文字与图标，避免只靠颜色区分。
- 路由按页面拆包；宣传页与签到页不加载后台表格逻辑。
- 列表筛选输入 300ms 防抖；旧请求被取消，过时响应不覆盖新结果。
- 大屏页面在离开时清理倒计时定时器。

## 9 维护约定

1. 颜色、间距、圆角、动效时长只从 `tokens.css` 取值，不写死色值。
2. Element Plus 通过 `element-theme.css` 映射变量，组件级覆盖集中在该文件。
3. 新增页面时在 `router/routes.ts` 登记标题、布局、鉴权与转场，不在页面内部另写转场。
4. 通用组件放 `components/common`，单页专用组件放对应业务目录；不在页面内复制同一套样式。
